# 本地同步 Release 附件到镜像平台

- 状态：已完成
- 类型：功能
- 分支：`feature/sync-bin`
- 完成日期：2026-10-09

## 变更摘要

新增主机侧 Python 工具，通过本机下载 GitHub Release 附件，再上传到 Gitee 和 GitCode 的对应 Release。GitHub 保持发布源，现有 Actions 继续负责同步 Release 元数据。

## 用户可见行为

- 支持指定 Tag、最新正式版或全部已发布版本，也可只选平台或精确附件名称。
- 根目录 `sync-release.cmd` 提供同步、预览和退出菜单；Tag 留空处理全部版本，替换选项留空默认不替换。
- 首次启动询问创建 `.venv` 和安装依赖，默认为是；已有健康环境直接进入菜单，失败时可重试。
- 默认读取 Windows 普通凭据 `Gitee`、`GitCode`，兼容环境变量及自定义凭据名称。
- 支持计划预览、仅下载、仅验证、自定义源与目标仓库、分别配置 GitHub 和镜像代理。
- 完整下载缓存会复用并重新检查哈希；上传后重新下载远端附件，SHA-256 一致才报告成功。
- 默认跳过同名附件，仅补传缺失并删除多余附件；显式 `--force` 时替换全部选中的同名附件。
- 下载、上传、验证使用单行进度条和转圈动画；成功为绿色、错误为红色、警告为黄色，重定向时保留简洁普通日志。
- 某个平台失败后继续处理其他可处理项，最终用非零退出码反映失败。

## 设计与实现

- Gitee 使用 Release ID 的 `attach_files` API，采用流式 multipart 上传。
- GitCode 取得按 Tag、文件名生成的上传地址，携带返回的签名请求头以 `PUT` 上传；过滤远端的源码压缩包。
- 凭据通过 `CredReadW` 在当前 Windows 用户会话中读取，不写入缓存；跨域文件下载、对象存储上传不携带平台令牌。
- 缓存键包含源仓库和附件身份信息，本地路径使用哈希；临时文件与缓存清单分别原子替换。
- 同一缓存目录通过独占锁限制并发。GET 可重试，上传响应不确定时重新查询远端，不盲目重复写请求。
- 补传、替换成功后删除多余附件；任一步失败时暂停该平台清理。附件筛选不改变完整源清单，源码包不参与删除。
- 环境检查及初始化仅使用标准库；依赖损坏时修复 pip 并重装所需依赖，保留虚拟环境内的其他文件。
- 独立渲染线程维持动画，传输线程更新字节数；共享锁避免提示信息与进度相互覆盖。异常或中止后清理动态行，不隐藏光标。

## 兼容性与边界

- 需要 Python 3.10+ 及独立的 Requests、requests-toolbelt 依赖，使用根目录 `.venv/` 虚拟环境。
- 目标 Release 必须预先存在；工具不会创建 Release、修改发布说明、同步 Git 仓库；补传和替换成功后删除多余附件。
- `--all` 包含预发布版、排除草稿；未执行全部历史版本的线上补传。
- 默认重跑只查询元数据，上传后和显式验证时下载校验会产生额外流量；中断文件重新传输，尚无字节断点续传。
- 替换不是原子操作；删除前校验源缓存，失败后可重跑补传，不再下载备份旧附件。
- 普通凭据可被同一 Windows 用户的进程读取，不能防御该用户环境中的恶意程序。
