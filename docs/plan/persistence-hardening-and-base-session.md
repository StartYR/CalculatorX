## 1. 目标与边界

第一阶段解决已有功能中的状态回退、默认值分叉、保存失败不可观察、待保存数据缺少生命周期收尾等问题。第二阶段利用补强后的基础设施，保存数值、整数、IEEE754 三种模式的完整可继续编辑状态。

本计划不改变换算算法、键盘布局、沉浸光感、历史数据库结构或网络接口。绘图只检查现有持久化兼容性，图片缓存拆分单独评估，不与本轮修复捆绑。

当前已有的设置和历史仍然有效；不得以清空整个 Preferences 文件或历史库作为升级手段。所有实施项在实际完成验证后再勾选，计划中的验收条件不代表已通过。

## 4. 目标职责与保存约定

### 4.1 基础层与模块层

| 层级 | 负责 | 不负责 |
| --- | --- | --- |
| PreferenceManager | 实例初始化、键值读写、合并提交、提交结果、错误记录 | 数值解析、汇率有效性、计算会话恢复 |
| 模块状态代码 | 快照结构、版本迁移、数据校验、内存最新状态、保存时机 | 复制另一套底层 Preferences 封装 |
| AppStorage | 全局设置及确实需要共享的响应式状态 | 自动把任意键变成业务真值来源 |
| RDB 历史 | 已确认计算记录及查询 | 代替当前未完成草稿 |

优先在现有文件与会话类上补充必要方法。只为明确的快照编解码职责新增小文件，不建设通用状态管理框架。

### 4.2 统一约定

- UI 更新、写入 Preferences 缓存、持久化完成是三个不同阶段；接口和日志必须区分。
- 已存在的简单 `set()` 调用保持兼容，并在内部处理异步失败；需要确认结果的路径使用可等待接口。
- 可等待的提交必须覆盖调用时已接受的修改；提交期间出现的新修改保持待提交，不能被旧完成回调误标为已保存。
- 多键合并提交减少重复调度，但不承诺数据库事务。必须一起解释的状态使用一个有版本号的记录。
- 未变化的数据不重复调度；失败后保留最新待保存状态，后续操作或前台恢复时有限重试，不无限立即重试。
- 初始化/读取失败与键不存在要能区分。临时读取失败期间不能把默认快照自动写回，覆盖尚未成功读取的数据。
- 保存失败不阻断输入；必要时以不挤占布局的轻提示告知无法保存，避免连续弹出。日志不包含用户输入正文或剪贴板内容。
- 后台及离开回调是补充保存机会，不能承诺断电、进程强制终止时最后一次按键绝不丢失。

| 数值 | `sourceText`、`sourceRadix`、`text`、`radix`、`places`、`evaluated`、`previewValid` | 从精确来源重建值与显示；不从舍入输出或带 `≈` 的文本恢复原值 |
| 整数 | 表达式、结果 HEX 位模式、位宽、进制、有无符号、Carry、当前 flags、previousFlags、evaluated | 64 位值不经过普通 Number；保留继续运算所需上下文 |
| IEEE754 | 草稿、格式、进制、确认位模式、可选的最近有效预览位模式、确认及预览有效性 | 用 HEX 等无损字符串保留负零、NaN payload；确认值与预览分别保存 |

- [ ] 未完成输入例如 `1e-` 保留草稿和上一有效显示；错误提示按恢复后的状态重建，不序列化运行时异常对象。
- [ ] 不恢复菜单、帮助窗、滚动位置、动画、展开面板或撤销/重做栈；键盘初始显示。
- [ ] 验证枚举、文本长度、位宽、位模式和字段关系；不一致数据不得通过静默截断变成另一个数。
- [ ] 单一模式损坏时独立回退；整份 JSON 无法解析时回退设置与默认会话，并保留有界诊断副本。
- [ ] 未知更新版本的快照保留原始记录，当前运行可使用默认会话，但禁用覆盖该未知记录，直至具备迁移或明确重置路径。

检查点：导出再恢复后，继续输入、确认、改变进制及操作 Carry 的结果，与未重启会话一致。

### S7：接入进制转换保存生命周期

主要文件：`components/exchange/base/BaseConverter.ets`、快照代码和配置键。

- [ ] 恢复优先级：最新进程内会话 → 有效磁盘快照 → 旧 `KEY_PROGRAMMER_SETTINGS` → 默认值。
- [ ] 有效快照中的配置与内容一起恢复，不能再被独立旧设置覆盖位宽或进制。
- [ ] 旧版本只有设置时恢复配置与零值会话，不擅自从历史中抽取一条记录作为上次输入。
- [ ] 在 `apply`、撤销、重做、粘贴、历史回填及配置变化后更新内存快照并安排保存。
- [ ] 普通输入默认 400 ms 防抖、最长等待 2 s；确认、AC、离开页面和后台请求立即保存。
- [ ] AC 只保存当前实际清空后的会话，不额外清除其他模式；清除历史不清除当前会话。
- [ ] 恢复操作不模拟 `=`，不新增历史、不振动、不制造撤销记录。
- [ ] 清空、重入与后台回调共享提交顺序，防止旧延迟任务使已清除的内容复活。

检查点：三个模式均可跨重启继续编辑；合法未完成草稿、确认位模式和最近有效预览不会相互覆盖。

- [ ] 若需更新其他仓库的协议网页，在实施阶段明确文件范围后单独处理，本计划不直接修改站点。

## 6. 最小有效验证矩阵

| 范围 | 场景 | 预期 |
| --- | --- | --- |
| 基础提交 | 延迟完成、异步失败、提交中继续更新 | 可观察完成/失败，最新状态保持待保存，旧回调不覆盖新值 |
| 初始化 | 首次安装、已有设置、单键类型错误、存储读取失败 | 默认值一致，有效旧值保留，读取失败不触发破坏性回写 |
| 汇率重入 | 输入/排序/切换活动项后切换模块，包括防抖期间 | 回来仍是最新状态，之后重启一致 |
| main 行为回归 | 离线、缺少汇率、非正数、无效数值、点击 `--` 项 | 非活动结果为 `--`，金额不被占位符污染，USD 基准正常 |
| 汇率缓存 | 同小时命中、跨整点、请求失败、空/部分有效响应 | 时间与有效数据对应，失败保留已有缓存，不制造虚假等值结果 |
| 迁移 | 只有旧键、新旧并存、坏 JSON、未知快照版本 | 迁移不丢合法值，不混合两份配置，不覆盖未知版本 |
| 生命周期 | 防抖内切后台、页面销毁、快速重入、旧网络回调返回 | 最新状态提交，监听清理，旧任务不覆盖新会话 |
| 设置与绘图 | 连续拖精度、切换主题/振动、编辑多个函数后重启 | UI 与存储一致，绘图及迁移备份无回归 |
| 数值 | 十进制 `0.1` 转 BIN 后重启，再编辑原值；长数及未完成草稿 | 精确来源不变，显示精度不成为数值精度 |
| 整数 | 64 位全 1、有/无符号、未完成表达式、Carry 与标志位 | 位模式不失真，确认和后续运算等价 |
| IEEE754 | binary16/32/64、负零、无穷、NaN payload、`1e-` | 原始位与最近预览均恢复，草稿不覆盖确认值 |
| 清除与历史 | AC 后立刻离开/重启、清历史、历史回填 | 清空持久化；历史操作保持独立语义；恢复不新增记录 |

验证分层：

1. 纯编解码、校验、迁移与提交顺序使用针对性测试；复用现有 `tools/test-programmer.mjs`、`tools/test-numeric.mjs` 的核心测试方式。
2. 对实际修改文件执行静态检查和 `git diff --check`。涉及公共接口、资源等时按 AGENTS.md 执行必要编译，不为纯文档或每个小步骤重复构建。
3. 落盘使用正式 Ability Context；Preferences 缓存读回只证明内存状态，必须在等待提交后重启应用并从实际 UI 验证。
4. `ohosTest` 自身 Context 不能代替正式应用存储 Context；故障注入只操作测试数据并保留恢复路径。
5. 断电与强制终止场景若未实测，明确标记未验证；计划勾选表示对应实施项完成，不能替代设备验收。

## 7. 提交拆分与完成标准

建议每个主题在达到检查点后提交，不积累成一次大提交：

| 阶段 | 建议提交主题 |
| --- | --- |
| 当前计划 | `docs: 制定持久化补强与会话保存计划` |
| S1 | `fix: 补齐首选项提交结果与失败处理` |
| S2 | `fix: 统一启动配置加载与默认值` |
| S3 | `fix: 修复汇率状态恢复与快照保存` |
| S4 | `fix: 修正汇率缓存时间与后台保存` |
| S5 | `test: 覆盖已有持久化边界与恢复场景`，配套文档单独提交 |
| S6 | `feat: 增加进制转换会话快照与恢复` |
| S7 | `feat: 接入进制转换自动保存` |
| S8 | `test: 覆盖进制会话恢复与迁移边界`，配套文档单独提交 |

回归测试宜随对应修复一起提交，表中的测试提交用于跨模块补充，不把所有测试推迟到最后。每次提交前检查文件边界，不夹带其他分支改动。

完成标准：已有设置、汇率及绘图保存不回归；main 的 `--` 保护完整保留；基础提交可观察且失败可恢复；三个进制模式能无损恢复继续编辑；升级不清空存量数据；实际验证与未验证边界写入变更说明。
