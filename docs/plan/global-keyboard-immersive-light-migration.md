# 全局计算键盘沉浸光感迁移计划

- 状态：迁移实施完成；发布前广覆盖回归待补充
- 编写日期：2026-09-22
- 适用分支：`feature/api-26-sensation`
- 目标 API：`26.0.0`
- 最低兼容 API：`6.1.0(23)`，保持不变
- 完成结论：七类键盘均已接入可切换沉浸路径，并完成逐阶段真机验收
- 实施原则：旧键盘与沉浸键盘保持完整、独立的渲染路径；逐模块迁移、验证和提交

## 1. 计划目标

本计划用于把基础计算中已经验证的 API 26 原生逐键沉浸光感扩展到 CalculatorX 的全部计算键盘，同时新增一个统一的键盘沉浸光感开关。

最终行为固定为：

```text
API 26 及以上 + “键盘沉浸光感”开启
└─ 使用独立的沉浸键盘容器与按键表面

API 低于 26
或 API 26 及以上 + “键盘沉浸光感”关闭
└─ 使用完整的原有键盘容器与按键表面
```

该开关的“全局”范围是所有计算键盘，不控制 TopBar、Sheet、菜单、搜索框和弹窗等已经存在的沉浸光感。关闭键盘开关后，这些原有小型控件继续遵循各自现有逻辑。

## 2. 已验证的技术基线

基础计算试点已经提供以下真机证据：

- 自定义底部 TabBar Builder 可以承载多行 Grid，其后代普通按钮能够显示 API 26 原生 `uiMaterial.ImmersiveMaterial`；
- 19 个基础计算按键均有触点光效，输入、计算、退格、长按和触感功能正常；
- 普通、运算、危险和强调四类语义材质可以复用缓存实例；
- 浅色、深色模式均能保留原有语义区分；
- 系统降低沉浸光感强度时，按键效果同步降低，没有显示异常；
- API 23 回退显示正常；
- `entry/default/debug assembleHap` 已通过构建。

基础试点的最终结论见[基础计算键盘沉浸光感试点计划](./basic-keyboard-immersive-light-prototype.md)。

## 3. 不可突破的架构边界

### 3.1 两条渲染路径必须独立

每个键盘模块都必须提供两个明确的布局入口：

- `Legacy` 路径保留原有 `Column`、`Grid`、尺寸、背景、边框、阴影、点击缩放和状态样式；
- `Immersive` 路径使用经过验证的单 Tab 自定义底部 TabBar 容器，以及透明背景、系统材质、交互形变和点光源；
- 两条路径可以共享按键数据、文字或图标内容、Action 映射、触感和业务回调；
- 两条路径不得共用一套会在运行时混合旧背景与新材质属性的表面 Modifier；
- 关闭开关必须切换到完整 `Legacy` 组件树，不通过在沉浸结构上简单设置 `Material.empty` 模拟旧键盘。

这样设计后，未来不再支持 API 23 时，可以按模块删除完整的 `Legacy` Builder，而不需要从一组交错的条件属性中清理旧逻辑。

### 3.2 API 保护必须保持直接、正向

API 26 的 `uiMaterial.ImmersiveMaterial`、`ImmersiveStyle` 和相关属性只能出现在直接的：

```ts
if (deviceInfo.apiAvailable('26.0.0')) {
  // API 26 沉浸键盘
} else {
  // 完整旧键盘
}
```

正向分支中。偏好开关作为 API 26 分支内的第二个条件判断，不得让 API 23 路径求值或构造 API 26 材质对象。

### 3.3 不提前建立大一统键盘组件

各模块的布局、Shift、长按菜单、动态按钮、弹窗和焦点状态差异明显。迁移期间只共享已经稳定的低层能力：

- 键盘材质角色；
- 材质实例缓存；
- 全局开关状态；
- 必要的角色映射辅助函数。

在至少基础、矩阵、方程和科学四个模块完成后，再根据真实重复代码决定是否抽取公共视觉组件。不得为了追求统一而改变现有业务状态机。

## 4. 全局设置设计

### 4.1 配置语义

| 项目 | 最终值 |
| --- | --- |
| 常量名 | `PreferenceConfigs.KEY_KEY_IMMERSIVE_MATERIAL` |
| 持久化键 | `keyImmersiveMaterial` |
| 类型 | `boolean` |
| 发布默认值 | `false` |
| 设置项标题 | `键盘沉浸光感` |
| 设置项说明 | `为所有计算键盘启用系统材质与触点光效。关闭后使用经典键盘。` |
| 设置位置 | 设置 → 外观与体验，颜色模式之后、触感反馈之前 |
| 生效范围 | 基础、科学、方程、矩阵、汇率、图形主键盘和图形定义域键盘 |
| 生效时机 | 保存后立即更新 AppStorage；返回计算页面时无需重启应用 |

发布默认继续关闭，用于保护现有用户视觉并控制 GPU 成本。API 26 用户可以在设置中主动开启，已开启用户的选择会通过 Preferences 保留。

API 低于 26 时设置项不显示，持久化值即使存在也不参与布局判断。

### 4.2 状态流

实施时需要同时更新：

1. `CalculatorConfigs.ets`：新增稳定的偏好键常量；
2. `EntryAbility.ets`：在窗口创建时把持久化值注入 AppStorage，保证首屏读取稳定；
3. `PreferenceManager.ets`：在 `loadAllToAppStorage()` 中同步同一默认值；
4. `Settings.ets`：使用 `@StorageLink` 显示和修改开关，并调用 `PreferenceManager.set()` 落盘；
5. 各键盘外壳：使用 `@StorageProp` 读取开关，不在按键实例中重复读取 Preferences。

当前项目同时存在 `EntryAbility` 的启动注入和 `PreferenceManager.loadAllToAppStorage()` 的集中同步。本计划只把新键加入两条现有路径，不顺带重构偏好初始化机制。

### 4.3 设置开关自身的可访问性

- 为 Toggle 设置稳定 Semantic ID；
- `accessibilityText` 反映当前布尔状态；
- 标题和说明不能只依赖图标传达含义；
- API 23 隐藏整行设置项时，不保留不可操作的空白或分隔线。

## 5. 键盘清单与迁移风险

| 顺序 | 键盘 | 当前入口 | 结构特点 | 风险 |
| --- | --- | --- | --- | --- |
| 1 | 基础计算 | `components/BasicCalc.ets` | 单个 5×4 Grid，等号跨行；沉浸原型已完成 | 低 |
| 2 | 矩阵计算 | `components/MatrixCalc.ets` | 单个 6×5 Grid，另有矩阵维度弹窗 | 低 |
| 3 | 方程求解 | `components/EquationSolver.ets` | 上下双 Grid、Shift、长按菜单 | 中 |
| 4 | 科学计算 | `components/ScientificCalc.ets` | 上下双 Grid、动态 Shift、长按菜单和气泡层级 | 中高 |
| 5 | 汇率换算 | `components/exchange/rates/ExchangeKeyboard.ets` | 260vp 可展开键盘，挂在列表底部 Stack | 高 |
| 6 | 图形主键盘 | `components/graphing/GraphingEditSheet.ets`、`GraphingKeyboard.ets` | 全屏 Sheet 内的动态悬浮双 Grid，依赖编辑焦点与收起动画 | 很高 |
| 7 | 图形定义域键盘 | `components/graphing/GraphingKeyboard.ets` | `TextInput.customKeyboard()` 小键盘，独立焦点与光标状态机 | 很高 |

迁移顺序依据容器复杂度和业务状态风险，不依据文件大小。任何模块验证失败时停止该模块，不影响已经完成的前序模块。

## 6. 公共材质语义

最终使用六类材质角色：

| 角色 | 典型按键 | 表面策略 |
| --- | --- | --- |
| `NORMAL` | 数字、点、百分号、普通函数 | 保留系统超薄材质的基础表面 |
| `OPERATOR` | 加减乘除、常规运算符 | 使用轻量中性色赋色 |
| `DANGER` | AC、退格、清除 | 使用高不透明度危险色赋色 |
| `EMPHASIS` | 等号、EXE、确定 | 使用高不透明度强调色赋色 |
| `SHIFT` | 未激活 Shift | 保留旧键盘的橙色状态 |
| `SHIFT_ACTIVE` | 已激活 Shift | 保留旧键盘的深橙色状态 |

第一轮复用基础计算已经验收的材质参数：

```text
style: ULTRA_THIN
interactive: true
lightEffect: {}
```

颜色从浅色和深色主题资源读取。矩阵键盘真机验收发现四类角色无法表达旧版 Shift 状态，因此新增 `SHIFT` 与 `SHIFT_ACTIVE`；分数、求逆、转置等函数键则按旧版背景规则归入 `OPERATOR`，保持原有主副层级。

以下做法不进入全局方案：

- 为每个按键创建单独材质对象；
- 用完全不透明背景覆盖材质滤镜；
- 使用 `colorInvert` 修正表面颜色；
- 在 API 23 路径中复用透明按钮表面；
- 同时保留系统交互形变和旧版强缩放、透明度、阴影变化。

| --- | --- | --- |
| API 23 | 不显示 | 完整旧键盘 |
| API 26 | 关闭 | 与 API 23 相同的完整旧键盘 |
| API 26 | 开启 | 独立沉浸键盘 |

API 26 还需覆盖系统沉浸光感关闭或降低、默认和较高强度。系统强度变化应只改变系统材质表现，不改变应用开关值或键盘业务状态。

### 8.2 主题与窗口

- 浅色、深色、跟随系统切换；
- 手机竖屏；
- 小窗与受限高度；
- 横屏；
- 条件允许时补充平板；
- 底部导航区域高度发生变化时不重复避让。

### 8.3 通用交互

- 每个可见按键产生正确 Action；
- AC、退格单击和长按连续删除；
- Shift 开启、消费和恢复；
- 长按候选菜单、气泡层级和选择结果；
- 触感开关与振动风格；
- 公式区点击、滚动和结果输出；
- 模块切换、返回、前后台恢复和主题切换；
- 设置开关持久化与返回页面后的即时生效；
- 开关切换前后的当前公式、矩阵、汇率或图形数据不丢失。

### 8.4 视觉

- 语义色、文字和图标对比度；
- 材质圆角、高光和触点光源完整；
- Grid 或 TabBar 不裁剪外发光；
- 系统阴影与旧阴影不重复；
- 旧点击缩放与系统交互形变不叠加；
- 等号跨行、特殊跨列和空占位不变形；
- 系统降低光感后仍能辨认按钮边界。

### 8.5 性能

- 每个模块快速连续输入 30 秒；
- 科学、方程和图形模块打开长按菜单后继续输入；
- 汇率与图形键盘重复展开和收起；
- 深浅色和开关切换后继续操作；
- 观察点击延迟、掉帧、温度和异常 GPU 占用；
- 确认同角色按键复用材质实例，没有在每次 `build()` 中重复构造。

## 11. 停止与回退条件

任一模块出现以下情况时，停止该模块迁移并回到最近检查点：

- 必须使用嵌套 Tabs、负边距或屏幕坐标硬编码才能维持布局；
- 按键被无障碍系统错误合并成单一 Tab；
- 公式区、列表、Sheet 或按键出现点击拦截；
- Shift、长按菜单、退格、触感或业务 Action 回归；
- 开关关闭后仍残留透明按钮、系统阴影或新容器行为；
- API 23 求值 API 26 材质对象、崩溃或产生兼容告警；
- 系统降低光感后按键边界不可辨认；
- 快速操作出现可感知延迟、掉帧或异常发热；
- 为迁移一个模块而同时修改其他模块的业务逻辑。

回退单个模块后，全局开关仍可保留；未迁移模块必须继续固定使用旧键盘，并在设置说明或发布范围中准确描述当前覆盖情况。

## 12. 完成标准

- 全局开关在 API 26 可见、可持久化并无需重启；
- API 23 不显示开关且始终使用完整旧键盘；
- API 26 关闭开关时，所有模块与 API 23 复用同一旧键盘路径；
- API 26 开启开关时，所有已纳入范围的键盘使用独立沉浸布局；
- 深浅色、系统光感强度、窗口状态和核心交互通过真机验收；
- 语义色和材质缓存策略在各模块保持一致；
- 失败实验没有遗留死代码、无效资源或不可操作设置；
- Git 历史可以按设置、模块和容器实验分别回退；
- 最终文档准确列出已支持和未支持的键盘，不把未验证场景标记为完成。

代码迁移、逐模块真机验收和最终 debug 构建已经完成。小窗、横屏、平板、所有模块 API 23 真机覆盖及长时间性能测试属于发布前回归，不在本次阶段性验收中宣称完成。

## 13. 本计划不包含

- 不改变计算引擎、LaTeX 翻译、历史记录或数据持久化语义；
- 不重写 `KeyGestureWrapper` 的手势状态机；
- 不把 TopBar、Sheet、菜单、搜索框和弹窗纳入键盘开关；
- 不在迁移期间合并科学、方程和图形键盘的业务组件；
- 不用自研光效替代未通过原生区域验证的键盘；
- 不提高最低兼容 API；
- 不在同一提交中同时迁移多个键盘模块。
