## 1. 计划目标

本计划用于把当前仅显示占位内容的进制转换模块建设为 CalculatorX 的程序员模式。首轮优先完成固定字长整数、位运算、移位与旋转、进位与溢出、整数编码观察以及 IEEE 754 浮点表示；普通数值转换留到程序员模式稳定后实施。

程序员模式处理的是固定宽度位模式。同一串二进制数据会根据字长、符号解释和编码方式产生不同数值，因此实现必须把“原始位模式”“数学解释”“表达式运算”和“显示进制”分开管理。

最终目标：

- 支持 BIN、OCT、DEC、HEX 四种显示与输入进制；
- 支持 8、16、32、64 bit 固定字长；
- 支持无符号和二进制补码有符号整数运算；
- 展示原码、反码和补码的编码差异；
- 支持基础算术、位运算、逻辑/算术移位、循环移位和带进位循环；
- 展示 CF、OF、ZF、SF 和可控的 Carry In；
- 支持直接查看和编辑各个 bit；
- 支持 IEEE 754 binary16、binary32、binary64 的位模式与字段分解；
- 与 CalculatorX 的主题、触感、TopBar、模块切换、语义 ID 和历史体系保持一致；
- 为后续普通数值转换预留模式入口和共享显示组件，但不提前暴露未完成页面。

## 3. 产品结构与命名

### 3.1 模块层级

侧边栏继续使用“进制转换”，保持入口直观。模块内部最终形成两个顶层模式：

```text
进制转换
├── 程序员
│   ├── 整数
│   └── 浮点
└── 数值转换（后续实施，最终名称待定）
```

本计划实施期间只展示已经可用的程序员模式。数值转换完成前不显示无功能的模式页签，也不放置“敬请期待”按钮占用主界面。

### 3.2 程序员整数页面

页面从上到下分为：

1. 表达式与结果区；
2. HEX、DEC、OCT、BIN 同步值列表；
3. 字长、符号解释、编码观察和位视图入口；
4. CF、OF、ZF、SF 与 Carry In；
5. 五列程序员键盘。

四进制列表中，当前输入进制使用圆角背景、强调色标签和选中语义状态。其他行同步显示相同位模式的对应文本。程序员模式按字长补齐二进制、八进制和十六进制位数；十进制不补前导零。

### 3.3 程序员浮点页面

浮点页面与整数页面共享模块入口、主题和部分输入组件，但使用独立内容结构：

1. 浮点格式选择；
2. 十进制值、十六进制位模式和完整二进制位模式；
3. 符号位、指数位、尾数字段；
4. 分类、偏置指数、实际指数和有效数字说明；
5. 浮点专属输入键盘。

整数的有符号设置、CF/OF/ZF/SF 和整数移位不进入浮点页面。

## 4. 固定语义规则

本节是实现和测试的共同契约。若后续需要改变规则，应先更新计划和测试向量，再修改实现。

### 4.1 内部值模型

- 整数核心以固定宽度位向量作为唯一权威值；
- 支持宽度为 8、16、32、64 bit；
- 任何输入先解析为数学值或原始位串，再规范化为当前宽度的位向量；
- 所有整数操作完成后按当前宽度截断；
- 64 bit 路径不得依赖普通浮点 `Number` 保存完整整数；
- UI 不直接实现进制解析、位运算、标志位或溢出判断；
- 核心返回结构化结果，包括位模式、各进制文本、数学解释、标志位和诊断信息。

实现前进行一次最小技术验证，确认 ArkTS 下可维护的精确表示方案。候选方案可以是固定长度 bit 数组、两个 32 bit word 或精确字符串算法。选择标准为：64 bit 全范围精确、行为可测试、无隐式有符号转换、无需依赖 UI 和 WebView。若 ArkTS 方案无法同时满足这些条件，再评估隔离的 C++/N-API 核心；不得先以 `Number` 临时实现再把精度问题留给后续修补。

### 4.2 字长和别名

界面以位数为主，别名为辅：

| 字长 | 界面显示 | 无符号范围 | 补码有符号范围 |
| ---: | --- | --- | --- |
| 8 | `8 bit · BYTE` | 0 ～ 255 | -128 ～ 127 |
| 16 | `16 bit · WORD` | 0 ～ 65535 | -32768 ～ 32767 |
| 32 | `32 bit · DWORD` | 0 ～ 2³²-1 | -2³¹ ～ 2³¹-1 |
| 64 | `64 bit · QWORD` | 0 ～ 2⁶⁴-1 | -2⁶³ ～ 2⁶³-1 |

`WORD` 在 CalculatorX 中明确采用上述常见程序员计算器约定。`DB/DW/DD/DQ` 等汇编数据定义指令不属于首版范围。

### 4.3 字长切换

- 扩大字长时，无符号值执行零扩展；补码有符号值执行符号扩展；
- 缩小字长时保留低位并丢弃高位；
- 丢弃的高位改变数学解释时，界面显示一次明确的截断提示；
- 切换有符号/无符号只重新解释当前位模式，不改写位模式；
- 切换显示进制只改变输入和展示方式，不改写位模式；
- 字长切换后的表达式、结果和标志位必须同步，不能出现列表与键盘状态不一致。

### 4.4 整数编码

首版把运算模型和编码观察分开：

- 无符号与二进制补码参与完整表达式运算；
- 原码、反码和补码提供双向编码观察与转换；
- 原码和反码需要区分正零与负零；
- 8 bit 原码/反码范围为 -127 ～ 127，补码范围为 -128 ～ 127，其他字长按同一规则扩展；
- 选择无法表示的数学值时返回明确状态，不静默改成另一种编码；
- 原码和反码的完整算术语义不作为首版完成条件。

### 4.5 表达式

整数表达式首版支持：

- 字面量和括号；
- 一元正号、负号和按位非；
- 加、减、乘、除、MOD；
- AND、OR、XOR、NOT；
- SHL、SHR、SAR；
- ROL、ROR、RCL、RCR；
- 可选的 ADC 和 SBB，作为加减按键的长按能力，在基础加减与 Carry In 稳定后实施。

表达式中的字面量默认采用当前输入进制。首版不混用 `0x`、`0b` 等多种前缀；如以后支持前缀，必须先定义前缀与当前输入进制冲突时的优先级。

优先级从高到低固定为：

1. 括号；
2. 一元正负号、NOT；
3. 乘、除、MOD；
4. 加、减；
5. 移位与旋转；
6. AND；
7. XOR；
8. OR。

每次二元运算都在当前字长中得到结果。除法的有符号结果向零截断；MOD 的余数符号跟随被除数。除数为零返回明确错误，不更新有效结果和历史记录。

### 4.6 移位与旋转

- SHL：低位补零，高位移出；
- SHR：高位补零，按原始位模式执行；
- SAR：复制符号位，高位补符号位；
- ROL/ROR：在当前字长内循环；
- RCL/RCR：把 Carry In 与当前位模式组成 `字长 + 1` 位循环环；
- 普通移位计数大于或等于字长时，SHL/SHR 结果为零，SAR 根据符号位得到全零或全一；
- ROL/ROR 的计数按字长取模；
- RCL/RCR 的计数按 `字长 + 1` 取模；
- 移位计数为零时保持位模式和原有标志位，不制造新的 Carry Out。

这些规则是 CalculatorX 的确定性语义，不宣称完全模拟某个 CPU。首版不提供 x86、ARM 等处理器配置。

### 4.7 标志位

首版显示：

- `CF`：无符号加法进位、减法借位或最后移出的 bit；
- `OF`：补码有符号加减溢出；
- `ZF`：结果位模式是否全零；
- `SF`：结果最高位是否为 1；
- `C-in`：ADC、SBB、RCL、RCR 的输入进位，可由用户切换。

规则：

- 加减法更新 CF、OF、ZF、SF；
- 位运算更新 ZF、SF，并把 CF、OF 标记为不适用；
- 移位更新 CF、ZF、SF；OF 只在定义明确的单步场景显示，否则标记为不适用；
- 旋转更新 CF；其他未由该操作定义的标志保持或显示为不适用，具体行为在核心测试中固定；
- 单纯切换进制和有符号解释不产生新标志位；
- UI 使用 `0`、`1`、`—` 三态显示，避免把未定义状态伪装为零。

减法 CF 采用“发生借位时为 1”的规则。文档与界面帮助中说明这是一套 CalculatorX 规则，避免与采用相反 Carry 约定的体系结构混淆。

## 5. IEEE 754 首版边界

程序员模式完成整数能力后，再实施浮点表示。首版支持：

- binary16：1 位符号、5 位指数、10 位尾数；
- binary32：1 位符号、8 位指数、23 位尾数；
- binary64：1 位符号、11 位指数、52 位尾数；
- 十进制文本、十六进制位模式和二进制位模式之间的双向转换；
- 正零、负零、正规数、非正规数、正无穷、负无穷、NaN 分类；
- 展示符号位、存储指数、偏置、实际指数、尾数字段和解释后的有效数字；
- 位模式直接编辑和字段分色；
- 对 NaN 展示 quiet/signaling 和 payload 的可见信息，但不承诺跨平台保留所有 NaN payload 行为。

首版不包含：

- IEEE 十进制浮点格式；
- binary128；
- bfloat16；
- 浮点四则运算与异常标志；
- 用户可选舍入模式；
- 对某个 CPU 浮点环境的逐指令模拟。

十进制转 IEEE 位模式时，首版固定使用 roundTiesToEven。转换核心必须通过已知位模式向量验证，不以界面显示看起来接近作为正确证据。

## 6. 计划目录与职责

最终文件可以根据实现复杂度微调，但职责保持如下：

```text
entry/src/main/ets/
├── components/exchange/base/
│   ├── BaseConverter.ets             # 模块入口与模式装配
│   ├── ProgrammerMode.ets            # 程序员模式状态协调
│   ├── ProgrammerDisplay.ets         # 表达式与四进制同步值
│   ├── ProgrammerConfigBar.ets       # 字长、符号与编码设置
│   ├── ProgrammerFlagBar.ets         # CF/OF/ZF/SF/C-in
│   ├── ProgrammerKeyboard.ets        # 五列键盘与禁用状态
│   ├── BitEditor.ets                 # 可折叠位视图
│   └── Ieee754Panel.ets              # 浮点字段与位模式界面
└── utils/base/
    ├── BaseTypes.ets                 # 位宽、进制、操作符和结果类型
    ├── BitVector.ets                 # 固定字长位向量与格式化
    ├── ProgrammerEngine.ets          # 算术、位运算、移位、旋转和标志位
    ├── ProgrammerExpression.ets      # 词法、解析、优先级和求值
    ├── IntegerEncoding.ets           # 原码、反码、补码
    └── Ieee754Codec.ets              # binary16/32/64 编解码
```

约束：

- `components/exchange/base/` 只承载程序员模式业务组件和 UI 状态；
- `utils/base/` 不导入 ArkUI 组件，不读取页面状态，不触发振动；
- `Index.ets` 继续只负责挂载 `BaseConverter`，不得接收字长、进制或表达式局部状态；
- 通用按键组件只增加可复用能力，程序员专属操作表留在模块内；
- 不把程序员表达式送入 MathLive、SymEngine 或 Giac；
- 不使用 WebView 作为固定字长整数和 IEEE 位模式的中间层。

## 8. 核心测试矩阵

### 8.1 固定字长与进制

- 全零；
- 全一；
- 最高位为 1；
- 最大无符号值；
- 最大补码正数；

### 8.2 算术与标志位

至少覆盖：

| 场景 | 8 bit 代表值 | 预期重点 |
| --- | --- | --- |
| 无符号进位 | `255 + 1` | 结果 0，CF=1，OF=0 |
| 有符号溢出 | `127 + 1` | 位模式 `10000000`，CF=0，OF=1 |
| 负数溢出 | `-128 - 1` | 位模式 `01111111`，OF=1 |
| 借位 | `0 - 1` | 位模式全一，CF=1 |
| 零结果 | `1 XOR 1` | ZF=1 |
| 符号结果 | `0 - 1` | SF=1 |
| 除零 | `1 / 0` | 明确错误，不覆盖有效结果 |

### 8.3 移位与旋转

每个操作至少测试计数：

- 0；
- 1；
- `width - 1`；
- `width`；
- `width + 1`；
- 带 Carry In 为 0 和 1 的 RCL/RCR。

### 8.4 编码

- `+0` 与 `-0`；
- `+1` 与 `-1`；
- 原码/反码最大负数；
- 补码最小负数；
- 同一位模式在三种编码下的不同解释；
- 不可表示值的诊断。

### 8.5 IEEE 754

每种格式至少覆盖：

- `+0`、`-0`；
- `1`、`-2.5`；
- 最小正非正规数；
- 最大非正规数；
- 最小正规数；
- 最大有限值；
- `+∞`、`-∞`；
- quiet NaN 和 signaling NaN 代表位模式；

## 10. 完成条件

满足以下条件后，程序员模式才可标记为完成：

1. 固定字长核心在 8/16/32/64 bit 下保持精确；
2. 四种进制输入输出可稳定往返；
3. 算术、位运算、移位、旋转和标志位符合第 4 节；
4. 原码、反码、补码边界与正负零处理正确；
5. IEEE binary16/32/64 已通过特殊值和边界向量；
6. 程序员整数与浮点页面在目标设备上可操作；
7. 核心语义具有自动化回归，关键界面具有稳定语义 ID；
8. 历史与偏好恢复不会破坏既有数据；
9. README、架构、测试和变更说明与实际实现一致；
10. 未完成的普通数值转换仍被明确标记为后续能力。

构建成功不能代替核心向量、真机交互和视觉验收。静态检查、单元测试、构建、安装和真机验证应分别记录，不能互相替代。

## 11. 风险与停止条件

### 11.1 64 bit 精度

风险：ArkTS 普通数值路径可能在 `2^53` 以上丢失整数精度。

停止条件：无法证明全范围精确时，停止 UI 接入，先更换内部表示方案。

### 11.2 CPU 语义差异

风险：不同体系结构对减法 Carry、移位计数和部分标志位的定义不同。

处理：执行第 4 节的 CalculatorX 固定语义；未定义状态显示 `—`；首版不提供 CPU 模拟标签。

### 11.3 页面信息过密

风险：四进制列表、配置、标志位、位视图和五列键盘在小窗口中互相挤压。

处理：显示区动态压缩，位视图默认折叠，长内容滚动；任何阶段出现点击区域不足时，先解决布局再增加新控件。

### 11.4 长按功能不可发现

风险：OR/XOR/NOT 和旋转只放在长按菜单中，用户可能无法发现。

处理：按键增加副功能提示，首次使用提供简短引导，帮助文档列出所有操作。

### 11.5 范围失控

风险：程序员模式继续扩展为完整汇编器或特定 CPU 模拟器。

停止条件：需求涉及寄存器、指令编码、CPU 专属异常或完整浮点运算环境时，先建立独立后续计划，不并入 v1.7.0 基线。

## 12. 本计划不包含

- 普通数值转换的具体实现；
- 任意精度小数和 2～36 进制完整产品界面；
- x86、ARM 或其他 CPU 的逐指令模拟；
- 寄存器、内存、汇编执行器和指令编码；
- DB/DW/DD/DQ 汇编数据声明；
- 自定义任意 bit 字长；
- IEEE decimal32/64/128、binary128 和 bfloat16；
- 浮点四则运算、异常标志和多舍入模式；
- 因实现本模块而重构其他计算器、FormulaScreen 或 CAS 管线。
